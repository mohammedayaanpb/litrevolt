# AI provider validation

Offline tests verify transport contracts, result validation, recovery, and PDF rendering. They cannot establish current model access or equivalent grading quality between providers. The optional live benchmark uses a generated synthetic paper; it never reads the user's library or stored API keys.

## Offline checks

Run `pnpm check`. The `ai-paper-input` suite renders real PNGs and checks page order, dimensions, opaque white backgrounds, and the position of vector graphics. It also checks managed-path containment through directory junctions, byte and page limits, source-page mismatch, text extraction, and private AI access while the reader's closed-book quiz remains locked.

The synthetic three-page fixture contains a figure, a table, an equation, and explicit study limitations. Known answers cover a 3:2 figure ratio, nine versus six completed trials, six joules for three meters, and lack of evidence for outdoor reliability. The fixture is generated by `makeAiPaperPdf` in `tests/fixtures/ai-paper.ts` and contains no user data.

## Optional live benchmark

Live validation is disabled by default and incurs provider API charges. Run it only after an operator explicitly chooses to spend those credits. Inject the following environment variables through your local secret-management mechanism; do not commit keys or place them in command history:

- `LITREVOLT_LIVE_AI=1`
- `LITREVOLT_LIVE_PROVIDER=anthropic`, `openai`, `kimi`, or `gemini`
- `LITREVOLT_LIVE_API_KEY` for that provider
- Optional `LITREVOLT_LIVE_MODEL` and, for Anthropic, `LITREVOLT_LIVE_WORKSPACE_ID`

With those variables set, run `node node_modules/vitest/vitest.mjs run tests/ai-live.test.ts`. The benchmark normally makes six operations: a synthetic visual/JSON connection check, quiz generation, grading correct and incorrect answers, and evaluating accurate and inaccurate summaries. SDK and validation retries can increase the number of requests. Clear the opt-in variables afterward so ordinary test runs remain offline.

For Gemini, the default preset is `gemini-3.8-flash`; override it only with a
model available to the test account. Model access and free quotas depend on
that account, so an optional free tier does not guarantee that this benchmark
or grading is free. No live Gemini result is implied by passing offline tests.

Passing requires the correct visual JSON answer, five mixed-type quiz questions, valid page quotations, at least 75 points for correct quiz answers, a 40-point quiz separation, and a 30-point writing separation. Output includes only aggregate scores, citation counts, provider/model identity, elapsed time, and pass/fail status. Failures do not print SDK bodies, source documents, or model responses. The test deletes its temporary synthetic library after completion.

These thresholds are a smoke test, not proof of calibrated or equivalent evaluation. Before a release, run each supported model on the same fixed set of research papers and reader submissions, with explicit permission to send those documents. Include two-column text, equations, figure-dependent conclusions, ambiguous claims, incorrect answers, and justified criticism. Have a human review correctness, quotation grounding, and rubric fairness; record the exact model ID, per-operation latency, retry rate, and observed billed cost. Compare providers using those same inputs rather than expecting identical numerical scores. Keep any research content and detailed responses out of public test logs.

## Current application bounds

LitRevolt rejects source PDFs over 30 MiB or 600 pages. These are application ceilings, not a promise that every model can accept a document at the ceiling. Native PDF requests retain the complete PDF and page text. Kimi receives every page as a PNG plus page text, with each image capped at 2048 pixels on its longest side and at most 2x PDF scale. The image preparation budget is 90 million base64 characters; the adapter also checks the entire serialized request.

The provider adapters apply stricter transport limits where required: Anthropic requests are capped at 32 million bytes and custom Anthropic models use a conservative 100-page limit; OpenAI and Gemini requests at 50 million bytes; Kimi requests at 100 million bytes. Gemini retains the complete PDF inline with page text through its native API. Model context and output limits can still reject a smaller request. Errors preserve submitted work and require a suitable model or smaller complete paper. No provider path silently omits pages or falls back to text-only input.
